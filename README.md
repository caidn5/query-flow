# query-flow：问数智能体的查数前置流程 skill

给「能用自然语言查数的智能体」（NL → DAX/MDX）装载的一层**查询行为约束**：收到查数请求后、执行查询前，必须走完 **拆解 → 检索 → 核对 → 取用** 四步——每个字段的口径都有元数据与知识库**双重出处**，才允许执行。

## 为什么做这个

让 LLM 直接对着数据库自由组句，实测有四类高发失败（全部来自真实问数智能体的运行记录）：

1. **字段幻觉**：引用不存在的度量，或回落到模型默认度量 `[__Default measure]`，查询报错；
2. **静默假数据**：DAX 失败后 MDX 兜底返回假值（如恒为 1），答案看起来正常；
3. **口径自创**：问「平均铺货率」，agent 自己发明加权平均口径，数字是错的但很自信；
4. **精确等值必空**：品牌过滤写 `[品牌]="X"`，撞上一牌多写法（中文名/子线/大小写变体）必空，然后如实回答"没有数据"——**误报比报错更糟**。

本 skill 的路线是：**不指望模型「更聪明」，而是把组句环节改造成检索与核对**——语句结构预写进知识库，agent 只负责定位、核对占位符、原文取用。

## 四步流程 + 出口

```
① 拆解：问句 → 六槽拆解卡（时间/范围/指标/拆分/过滤/形态），关键词一律取问句原词
② 检索：DMV 全量拉回建两本底册（字段底册 + 度量底册），组句的每个标识符只能来自回执原文
③ 核对：两级裁定——语义优先，关键词子串模糊兜底；单命中采用、多命中停下问用户、零命中换别名重试后如实答"查不出"
④ 知识库用法核对：检索「字段字典」定位目标字段行，必读其聚合规则 + 使用说明两列
出口：该行有预写查询语句 → 原文复制、仅替换【占位符】执行，禁改结构；无预写语句才按模板骨架自组
```

## 七条铁律（SKILL.md 全文）

1. 字段必须存在于元数据，核对到「表+列」——列挂在别的表下 ≠ 本表有此列
2. 元数据查询全量拉回、本地过滤，不在语句里写 WHERE 试运气
3. 关键词匹配一律子串模糊、禁精确等值
4. 多命中必停，向用户列命中清单确认
5. 零命中禁直接答"没有数据"——先换别名，仍零才如实报告并附已试关键词
6. 报错/空返回先逐标识符回执核对，禁绕过核对换姿势重查
7. 指标查数必经「字段字典」核对——只抄语句不读规则同样违规

## 两个值得展开的设计

**知识库双重出处**：模型元数据（DMV 回执）回答"有没有"，字段字典（七列多维表：字段名称/所属表/元素类型/聚合规则/使用说明/关联度量/查询语句）回答"怎么用"。两者冲突时以模型元数据为准并向用户声明——知识库可以过期，模型不会。

**聚合规则档位 + 预写语句**：字段字典给每个指标标注聚合规则档位（直接引用度量 / 可 SUM 累加 / 仅明细取值 / 须 Σ÷Σ 加权 / 文本参数 / 仅分组筛选），并预写整条可执行查询。用户问法与档位冲突时（如对"仅明细取值"的指标求平均），agent 停下说明正确口径，禁硬算——**问法不改变口径，口径只认登记**。

## 演进时间线

| 版本 | 事件 |
|---|---|
| 起源 | 一品牌被答"没有数据"：精确等值撞上品牌碎片化写法（判例成为铁律 3） |
| v1.x | 三步流程（拆解卡 / 元数据底册 / 两级裁定）上线，字段幻觉与误报显著下降 |
| 实战暴露 | agent 不读知识库、读了仍自创口径、引用默认度量报错、MDX 兜底静默返回假值 |
| v2.0 | 新增第④步知识库用法核对 + 查询语句库（预写整条 EVALUATE，agent 只替换占位符）；七条铁律齐备 |

## 使用

1. 本 repo 整体作为 skill 装载到问数智能体（Claude Code 放 skills 目录；其他宿主打 zip 上传技能位）
2. 在宿主知识库侧配套建一张「字段字典」表（七列 schema 见 SKILL.md 第④步），为每个已登记指标填聚合规则、使用说明与预写查询语句
3. 智能体收到查数请求即触发四步流程；答案随附实际执行的查询语句原文，供人工核对口径与复跑

> 仓库说明：本 repo 为方法论本体。示例中的表名（F01/F02 线上/线下示例表）、品牌（BrandA 及其变体写法）、字段行数均已通用化，替换为你自己的模型与字段字典即可；流程与铁律不含业务假设。
